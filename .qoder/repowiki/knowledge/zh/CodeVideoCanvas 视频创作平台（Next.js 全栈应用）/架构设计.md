采用 Next.js App Router 全栈模式：`src/app/(app)` 为带侧栏壳的应用路由组，`src/app/api/*` 暴露 REST 入口（director/stage、render、artifacts、projects、settings），前端组件位于 `src/components/ui` 与 `src/app/_components`。

核心业务按 feature 切分为 `src/features/{canvas,director,render,audio,ai,artifacts,navigation}`，每个 feature 自包含 schema、service、queue-handler 与测试；`src/lib` 提供跨 feature 的基础设施（db、storage、queue、determinism、gsap、hooks、layout、motion）。

Director 流水线是应用中枢：`types.ts` 声明 `PIPELINE_STAGES = [INGEST,DIRECT,SHOT_SPEC,FABRICATE,ASSEMBLE,FINALIZE]`，`pipeline.ts` 提供有序元数据；`stage-runner.ts` 作为无副作用的默认执行器，首次调用时才打开 SQLite，负责加载上下文 → 构建 prompt → 创建 Pi Agent 会话 → 运行工具链 → 写入产物 → 提交结果；`runtime-repository.ts` 封装从 canvasNodes/artifacts 表按 stage 角色解析输入（`resolveAssembleInput`/`resolveFinalizeInput`），并通过 `materializeShotLanes` 在 INGEST 后幂等物化 shot-script/codegen/sfx/subtitle/qa 五节点通道。

Pi Agent 集成位于 `pi-session.ts`，使用 `@earendil-works/pi-agent-core` + `@earendil-works/pi-ai` 对接 StepFun OpenAI 兼容端点，会话以 JSONL 持久化到 StorageAdapter 管理的 `pi-sessions/` 目录；`session-store.ts` 负责会话创建/恢复与路径越界校验。

Prompt 层按 stage 拆文件：`prompts/{ingest,direct,shot-spec,fabricate,assemble,finalize}.ts`，每个文件同时定义 Zod inputSchema 与 buildXxxPrompt，由 `stage-prompt.ts` 根据 stage + nodeType 分发；`stage-result.ts` 将不可信模型文本归一化为 `PreparedStageResult`（含 renderSpec、ingestShots）。`tools/write-artifact.ts` 是可信写服务，对 shot-plan/deterministic-html/non-empty 三类产物做预校验后再落盘。

渲染子系统独立于 Director：`render/renderer.ts` 的 `HyperframesRenderer` 执行 guard→cache→capture→encode→commit 流程，依赖 `ffmpeg-static` 与 Playwright 帧捕获；`repository.ts` 负责 export plan 计算与缩略图索引。

数据库使用 Drizzle ORM + better-sqlite3，schema 位于 `src/lib/db/schema.ts`，迁移输出至 `src/lib/db/migrations`，`drizzle.config.ts` 指定 dialect=sqlite；项目初始化时 `createProject` 在单事务内插入全局 DAG（script-import→shot-split→score→export）及初始边。

依赖方向：API routes → features → lib；features 之间仅通过共享 schema 与 `lib/storage`、`lib/db/client` 耦合，feature 内部不反向引用 app 层。
