本项目采用基于 Next.js 的全栈单仓构建体系，以 pnpm 为包管理器，通过 npm scripts 组织开发、构建、测试与数据库迁移等流程，未引入 Makefile、Dockerfile 或 CI 流水线文件。

**构建工具链**
- 构建器：Next.js App Router（`next build` / `next dev` / `next start`），输出为 Node 服务端渲染应用，非静态导出。
- 类型检查：TypeScript（`tsc --noEmit`），配置在 `tsconfig.json` 中启用 strict、isolatedModules、bundler 模块解析及 `@/*` 路径别名。
- 代码质量：ESLint（`eslint .`）+ Tailwind CSS v4 + PostCSS。
- 测试：Vitest（`vitest run` / `vitest`），环境为 node，测试文件匹配 `src/**/*.test.ts`，并通过 `vitest.config.ts` 配置 `@/*` 别名。
- 数据库：Drizzle ORM + SQLite，通过 `drizzle-kit generate` 生成迁移，`pnpm db:migrate` 执行迁移（调用 `scripts/setup/db-migrate.ts`）。

**脚本组织**
根 `package.json` 的 `scripts` 字段是统一的入口：dev/build/start/lint/typecheck/test/db:*。辅助脚本集中在 `scripts/` 目录，按用途分 `setup/`（环境初始化）、`build/`（构建辅助）、`deploy/`（EdgeOne Pages 部署）、`dev/`（开发辅助）、`spikes/`（技术预研）。每个子目录均有 README 说明职责，脚本命名遵循 kebab-case，Node 脚本使用 `.mjs` 或 `.ts` 后缀。

**原生依赖处理**
`next.config.ts` 通过 `serverExternalPackages: ['better-sqlite3', 'ffmpeg-static']` 将原生依赖标记为外部包，避免 Turbopack 重写成 `/ROOT` 占位路径，确保运行时由 Node 正确解析。
`pnpm.overrides` 中强制锁定 `better-sqlite3` 版本，`onlyBuiltDependencies` 仅允许这三个包进行原生编译。

**制品与输出**
- 构建产物位于 `.next/`（Next.js 默认）。
- 数据库文件位于 `.data/app.db*`（SQLite WAL 模式）。
- Playwright E2E 截图与日志位于 `.playwright-cli/`。
- 临时测试结果位于 `tmp/results/`。
- `output/` 目录存在但当前为空，可能用于未来静态导出或中间产物。

**文档化构建资产**
`docs/video-director/` 是一个独立的 skill 项目，包含自身的 `package.json`、模板、Schema、脚本与测试，作为可复用的导演能力被独立维护，但通过 `tsconfig.json` 的 `exclude` 排除出主工程类型检查范围。

**约束与约定**
- 脚本规范：Shell 用 `.sh`，Node 用 `.mjs`/`.ts`，文件名 kebab-case，需支持 `--help`，危险操作前必须确认提示（见 `scripts/README.md`）。
- 测试文件统一以 `.test.ts` 后缀，存放于源码同级目录。
- 数据库迁移通过 Drizzle Kit 生成到 `src/lib/db/migrations`，schema 定义在 `src/lib/db/schema.ts`。
- 未发现在根级存在 Dockerfile、docker-compose、Makefile 或 GitHub Actions 工作流文件；部署脚本目录 `scripts/deploy/` 目前仅有 README，实际 EdgeOne CLI 脚本尚未落地。
