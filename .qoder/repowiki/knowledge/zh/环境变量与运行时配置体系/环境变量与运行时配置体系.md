本仓库采用「环境变量 + SQLite 持久化设置表」的轻量配置方案，没有引入集中式配置库（如 dotenv、config-node 等），而是由各个模块按需读取 process.env 并配合本地数据库存储敏感或可热更新的值。

## 1. 配置来源与优先级
- 环境变量：所有运行期配置通过 process.env 注入，示例见 .env.example，包含 StepFun API Key、Base URL、各模型 ID 以及本地数据目录 DATA_DIR。
- SQLite settings 表：通过 /api/settings 写入的键值对持久化到 src/lib/db/schema.ts 中 settings 表，用于存放 StepFun API Key 等敏感信息，避免硬编码或提交到版本库。
- 默认值：当环境变量缺失时，代码内提供合理默认值（如 https://api.stepfun.com/v1、step-3.5-flash）。

优先级顺序（以 API Key 为例）：
1. SQLite settings 表中 stepfun_api_key 的值（getStoredApiKey()）
2. 环境变量 STEPFUN_API_KEY
3. 调用方传入的显式参数

## 2. 核心文件与职责
- .env.example：全部可用环境变量的清单与说明，开发时复制为 .env.local
- src/lib/config/paths.ts：解析 DATA_DIR，导出 DB_PATH、ARTIFACTS_DIR，并提供 ensureDataDirs() 幂等创建目录
- src/features/ai/stepfun-adapter.ts：从 SQLite 读写 StepFun Key；构造 OpenAI 兼容客户端；校验 Key 可用性
- src/features/director/pi-session.ts：Director 运行时组装 StepFun provider，统一从 getStoredApiKey() ?? process.env.STEPFUN_API_KEY 取密钥
- src/lib/db/schema.ts：Drizzle schema 中的 settings 表定义（key/value/timestamp）
- next.config.ts：Next.js 构建期配置（serverExternalPackages 声明原生依赖）
- drizzle.config.ts：Drizzle Kit 迁移配置（dialect=sqlite, schema/migrations 路径）

## 3. 架构约定与设计决策
- 无前端暴露：所有涉及 process.env 和 DB 读写的模块都使用 'server-only' 标记，确保不进入浏览器 bundle。
- 按模块就近读取：没有统一的 getConfig() 入口，每个 feature 直接访问 process.env 常量，降低耦合度。
- 敏感配置落盘：API Key 通过 UI → API Route → SQLite 持久化，支持运行时更新而无需重启服务。
- 目录结构可配置：DATA_DIR 允许将 SQLite 与渲染产物迁移到其他磁盘位置，便于容器化部署。

## 4. 开发者应遵循的规则
1. 新增环境变量：在 .env.example 中添加注释说明，并在对应模块中以 process.env.XXX ?? 'default' 形式消费。
2. 敏感值不落仓库：API Key、密码等必须通过 /api/settings 写入 SQLite，禁止写死在源码或 .env 中提交。
3. 服务端限定：任何读取 process.env 或访问 DB 的模块顶部加 'server-only'，防止误入客户端。
4. 默认值兜底：对外部依赖（StepFun Base URL、模型名）提供合理默认值，保证本地开发开箱即用。
5. 路径初始化：使用 ensureDataDirs() 确保 .data 及 artifacts 子目录存在后再进行文件 IO。
