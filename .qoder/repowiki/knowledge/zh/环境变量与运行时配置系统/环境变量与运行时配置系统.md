本仓库采用「环境变量 + SQLite 持久化设置」的双层配置模型，核心围绕 StepFun（阶跃星辰）LLM 的 API Key、Base URL 与模型选择进行配置管理。

## 1. 配置来源与加载顺序
- **环境变量**：通过 process.env 直接读取，由 Next.js 自动加载 .env* 文件（.env.local、.env.development、.env.production 等），所有相关键以 STEPFUN_ 前缀命名：STEPFUN_API_KEY、STEPFUN_BASE_URL、STEPFUN_CHAT_MODEL/STEPFUN_TTS_MODEL/STEPFUN_ASR_MODEL/STEPFUN_VISION_MODEL。
- **SQLite settings 表**：生产环境 Key 通过 /api/settings POST 写入本地 SQLite，后续由 getStoredApiKey() 从 settings 表中按 key=stepfun_api_key 读取。
- **优先级**：在 Director Pi 会话中，getStoredApiKey() ?? process.env.STEPFUN_API_KEY；在纯 LLM 适配器中优先使用存储的 Key，未配置则回退到环境变量。

## 2. 关键文件与职责
- .env.example：环境变量契约文档，列出全部可配项及默认值
- src/features/ai/stepfun-adapter.ts：服务端专用：读写 SQLite settings 表、校验 Key、构造 OpenAI 客户端
- src/app/api/settings/route.ts：REST 接口：GET 返回配置状态（掩码 Key）、POST 保存并校验新 Key
- src/features/director/pi-session.ts：Director 运行时：注入 Provider、从存储或 env 取 Key、构建 StepFun Model
- src/lib/db/schema.ts：Drizzle schema：定义 settings 表（key/value/updated_at）

## 3. 架构约定
- 仅服务端访问：所有配置读取均位于带 'server-only' 标记的服务端模块中，绝不进入前端 bundle。
- 无集中 config 模块：当前没有统一的 config/ 入口，各组件按需从 process.env 或 getStoredApiKey() 拉取，属于轻量级散点式配置。
- Key 安全策略：API Key 不暴露给客户端（GET 只返回 configured 布尔和掩码字符串），校验失败返回 422 且不含敏感信息。
- 默认值内联：Base URL 与模型 ID 在各文件中以常量形式提供默认值，避免空指针。

## 4. 开发者应遵循的规则
1. 新增环境变量请在 .env.example 同步补充注释说明，并在所有消费处提供合理默认值。
2. 禁止在前端组件或客户端代码中直接引用 process.env.* 中的密钥；如需暴露非敏感开关，使用 Next.js NEXT_PUBLIC_ 前缀。
3. 生产环境的 API Key 必须通过 /api/settings 写入 SQLite，不得硬编码进代码或提交 .env* 文件。
4. 若引入新的第三方服务配置，参照 stepfun-adapter.ts 的模式：提供 getStoredXxx()/saveXxx() 函数，并通过对应的 API route 暴露 CRUD。
