## 1. 系统与架构概览
CodeVideoCanvas 采用「设置表 > 环境变量 > 内置默认值」的三层优先级配置模型，所有运行时配置通过统一的 resolver 函数按字段独立解析，并在设置页中暴露“生效值 + 来源”的可观测视图。配置分为两类：
- **应用级路径配置**（DATA_DIR、DB_PATH、ARTIFACTS_DIR）：仅由环境变量覆盖，不可在设置页修改。
- **AI 提供商配置**（StepFun、Gemini）：支持在设置页持久化到 SQLite `settings` 表，未设置时回退到环境变量或内置默认值。

该设计将敏感 Key 与业务参数统一纳入同一套加载/展示/保存流程，并通过 Drizzle ORM 的 `sqliteTable('settings')` 作为唯一事实源。

## 2. 核心文件与包
- `src/lib/config/paths.ts` — 本地数据目录与数据库路径解析（`DATA_DIR`、`DB_PATH`、`ARTIFACTS_DIR`），依赖 `process.env.DATA_DIR`。
- `src/features/ai/config.ts` — StepFun 配置的三层解析器（`getStepfunConfig`、`describeStepfunConfig`、`saveStepfunModelSettings`）。
- `src/features/ai/gemini-config.ts` — Gemini 配置的同类解析器（`getGeminiConfig`、`describeGeminiConfig`、`saveGeminiApiKey`）。
- `src/app/api/settings/route.ts` — Next.js API Route，统一 GET/POST 暴露配置读取与保存入口，含 Key 校验门禁。
- `src/lib/db/schema.ts` — Drizzle schema，其中 `settings` 表为键值对存储（key/value/updatedAt）。
- `.env.example` — 环境变量模板，声明所有可配置项及优先级说明。
- `next.config.ts` — Next 构建期外部包声明（`better-sqlite3`、`ffmpeg-static`），确保原生依赖在 Node 运行时解析。

## 3. 架构与约定
### 3.1 三层优先级解析
每个配置字段均遵循固定顺序：
1. 从 `settings` 表读取（`getSettingValue(key)`），空串或不存在视为 null；
2. 回退到 `process.env[ENV_KEY]`，经 `nonEmpty()` 去空白后判断；
3. 最后使用模块内 `DEFAULTS` 中的内置默认值。

该逻辑在 `resolveField` 中实现，并返回 `{ value, source: 'settings' | 'env' | 'default' }`，供设置页展示。

### 3.2 设置表作为唯一事实源
- `setSettingValue(key, value)` 写入时若值为空则删除该行，使配置自然回退到 env/default。
- `getSettingValue(key)` 读取空串也视为 null，保证“留空 = 回退”语义一致。
- StepFun 与 Gemini 的 settings key 命名统一为 `<provider>_<field>`（如 `stepfun_api_key`、`gemini_primary_model`）。

### 3.3 路径配置与环境变量
- `DATA_DIR` 是唯一可覆盖的数据根目录，默认 `<cwd>/.data`；`DB_PATH` 与 `ARTIFACTS_DIR` 由其派生。
- `ensureDataDirs()` 幂等创建目录，避免首次运行失败。
- 设置页 GET 返回 `storageDir` 用于前端显示当前 DATA_DIR，但明确注释“当前设置页不可改”。

### 3.4 API 层统一入口
`/api/settings` 提供：
- GET：返回 StepFun/Gemini 配置描述、路由、渲染并发数、存储目录等只读信息。
- POST：接收 stepfunSettingsSchema 校验后的 body，分别保存 apiKey、model settings、Gemini settings 与 Director routes；Key 提交时才触发 `validateKey` / `validateGeminiKey` 校验，失败返回 422。

## 4. 约定与约束
- **优先级不变式**：settings 表 > 环境变量 > 内置默认值，每条字段独立解析，测试用例覆盖了全部组合矩阵。
- **空值语义**：设置页留空 = 删除 settings 行 = 回退 env/default；环境变量空串等价于未设置。
- **Key 安全**：API 返回的 apiKey 始终掩码处理（`key.slice(0,3)***...`），不直接暴露明文。
- **服务端限定**：所有配置模块首行 `import 'server-only'`，禁止在客户端执行。
- **Schema 校验**：POST 请求体必须通过 `stepfunSettingsSchema.safeParse`，否则返回 400。
- **路径隔离**：`DATA_DIR` 仅在服务端/脚本/测试中使用（依赖 `node:fs`），前端不直接访问文件系统。
- **构建期外部包**：`next.config.ts` 显式声明 `serverExternalPackages`，防止 Turbopack 重打包原生二进制。

## 5. 扩展点
新增一个 AI 提供商只需复制 `config.ts` 的模式：定义 `SETTINGS_KEYS`、`ENV_KEYS`、`DEFAULTS`，实现 `getXxxConfig`、`describeXxxConfig`、`saveXxxSettings`，并在 `/api/settings` 中注册读写逻辑。现有 StepFun 与 Gemini 的实现已证明该模式的可复用性。
