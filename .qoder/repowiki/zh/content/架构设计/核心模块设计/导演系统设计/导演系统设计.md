- Pipeline 模式的工作流编排机制
- StageRunner 阶段执行器的工作原理
- SessionStore 会话状态管理机制

## 项目结构

## 核心组件
- Pipeline 编排：负责将多个 Stage 按拓扑顺序组织、调度与执行，支持并行与依赖约束。
- StageRunner 执行器：对单个 Stage 进行生命周期管理，包括前置校验、上下文注入、提示词生成、AI 调用、结果落盘与错误处理。**新增流式处理能力**。
- SessionStore 会话存储：维护一次导演任务的全局会话状态，提供读写隔离与一致性保障。
- RuntimeRepository 运行时仓库：持久化与查询运行时产物（如分镜计划、中间产物、最终制品），保证可追溯与幂等。**新增流式写入和增量更新**。
- StageResult 结果封装：统一阶段输出结构，包含成功/失败分支、副作用记录与元数据。
- StagePrompt 提示词组装：根据当前阶段与上下文动态拼装提示词，并绑定可用工具。
- PI Session 持久化会话：对外部 AI 服务的长会话抽象，支持断点续跑与上下文恢复。
- **新增** 流式事件处理器：处理实时事件推送和状态同步，支持SSE和WebSocket协议。
- **新增** 实时状态同步器：协调各组件间的状态更新，确保数据一致性。
- **新增** 输入契约验证器：确保各阶段输入输出的数据格式符合规范要求。
- **新增** 数据流管理器：协调阶段间的数据传递和状态同步。

## 详细组件分析

### Pipeline 编排引擎
- 职责
  - 声明式注册阶段与依赖关系
  - 构建有向无环图（DAG）并校验拓扑合法性
  - 按拓扑序调度 StageRunner，支持并发度控制
  - 聚合各阶段结果，提供进度与状态查询
  - **新增** 流式事件订阅和实时进度推送
- 关键流程
  - 初始化：收集所有已注册阶段，解析依赖，生成执行序列
  - 执行：按阶段就绪条件触发 StageRunner；失败时短路或按策略继续
  - 收尾：汇总结果、清理资源、更新全局状态
  - **新增** 流式处理：建立事件通道，实时推送执行状态
- 并发与容错
  - 基于队列与信号量控制并发
  - 支持阶段级重试与整体超时
  - 失败传播与部分成功报告
  - **新增** 流式任务的重试和断点续传

### 六阶段输入契约规范
**新增** 导演系统定义了六个标准阶段的输入契约规范，确保数据一致性和可预测性：

- 摄入阶段（Ingest）
  - 输入：原始素材URL、元数据、用户意图描述
  - 输出：素材清单、解析结果、初始分析
  - 验证规则：URL有效性、文件格式支持、大小限制
- 指导阶段（Direct）
  - 输入：素材清单、用户创作意图、风格偏好
  - 输出：高层创作决策、主题定位、叙事框架
  - 验证规则：意图完整性、风格一致性、创意可行性
- 制作阶段（Fabricate）
  - 输入：创作决策、素材清单、技术约束
  - 输出：镜头计划、片段脚本、技术参数
  - 验证规则：计划完整性、技术可行性、资源匹配
- 组装阶段（Assemble）
  - 输入：镜头计划、素材文件、特效需求
  - 输出：可渲染工件、合成配置、质量检查报告
  - 验证规则：文件完整性、格式兼容性、质量标准
- 收尾阶段（Finalize）
  - 输入：可渲染工件、导出配置、归档要求
  - 输出：最终制品、元数据、分发清单
  - 验证规则：输出格式、文件大小、元数据完整性
- 验证阶段（Validate）
  - 输入：任意阶段产物、验证规则、质量标准
  - 输出：验证报告、问题清单、修复建议
  - 验证规则：规则完整性、检测准确性、报告可读性

### SessionStore 会话状态管理
- 职责
  - 维护单次导演任务的会话键值空间
  - 提供原子写入、快照与回滚能力
  - 支持跨阶段共享上下文（如用户意图、中间摘要）
  - **新增** 状态变更事件监听和实时同步
- 特性
  - 内存优先、可选持久化桥接

### 阶段定义与执行顺序
- 阶段类型
  - 摄入（Ingest）：采集素材、解析元信息、生成初始清单
  - 指导（Direct）：依据意图生成高层创作决策
  - 制作（Fabricate）：细化到镜头/片段的生产计划
  - 组装（Assemble）：将多源产物整合为可渲染工件
  - 收尾（Finalize）：导出、校验与归档
  - **新增** 验证（Validate）：贯穿全流程的质量检查和验证
- 依赖关系
  - Direct 依赖 Ingest 的输出
  - Fabricate 依赖 Direct 的决策
  - Assemble 依赖 Fabricate 的计划
  - Finalize 依赖 Assemble 的产物
  - Validate 可插入任意阶段后执行
- 执行顺序
  - 线性主链：Ingest → Direct → Fabricate → Assemble → Finalize
  - 可在特定阶段旁路插入验证/修复阶段（由 Pipeline 拓扑决定）
  - **新增** 流式阶段：支持长时间运行的异步任务

### 错误处理与重试机制
- 错误分类
  - 可重试错误：网络抖动、限流、临时资源不可用
  - 不可重试错误：参数非法、阶段逻辑异常、数据不一致
  - **新增** 流式错误：连接中断、数据损坏、超时
- 策略
  - 指数退避 + 最大重试次数
  - 阶段级熔断：连续失败超过阈值则短路
  - 幂等保护：同一阶段多次执行需保证结果一致
  - **新增** 流式错误恢复：断点续传和状态补偿
- 观测
  - 记录错误码、上下文快照与堆栈摘要
  - 暴露进度与失败原因给 API 层
  - **新增** 流式错误监控和告警

## 故障排查指南

  - 运行时缺失：确认 RuntimeRepository 的产物是否存在且完整
  - AI 调用异常：检查 PiSession 的会话 ID 与消息历史
  - **新增** 输入契约违反：检查输入验证器的错误报告和违规详情

  - **新增** 流式错误：检查网络连接、事件丢失和缓冲区溢出
- 诊断手段
  - 开启调试日志，记录提示词与工具调用轨迹
  - 使用 check-determinism 工具对比两次执行差异
  - 通过 /api/jobs/:id 查询作业状态与阶段明细
  - **新增** 使用输入契约验证器报告定位数据格式问题
  - **新增** 流式事件监控和调试工具
- 恢复策略
  - 针对可重试错误执行自动重试
  - 针对不可恢复错误提供人工介入入口与回滚选项
  - **新增** 流式任务的断点续传和状态恢复
