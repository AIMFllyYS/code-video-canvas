# CodeVideoCanvas Product Spec v3

## 0. 文档合同

### 0.1 权威范围

本文是 v3 产品行为的唯一权威，定义用户能看见、操作和验收的结果。它不规定具体
数据库、编排器、Agent SDK、目录或部署供应商；技术实现由 `CVC-ARCH-V3` 约束。

### 0.2 规范用语

- **MUST / 必须**：不满足即产品验收失败；
- **MUST NOT / 禁止**：出现即产品验收失败；
- **SHOULD / 应当**：默认实现；偏离必须记录理由；
- **MAY / 可以**：不影响 v3 完成。

### 0.3 Requirement ID

需求 ID 一经发布不得改义。新需求新增 ID；废弃需求保留并标注 superseded，不复用
旧 ID。

## 1. 产品摘要

### 1.1 一句话定位

CodeVideoCanvas 是一个节点式 AIGC 视频创作引擎：用户导入文字稿，系统按语义拆成
分镜，为每个分镜生成可检查、可修改、可独立重渲的确定性代码视频，叠加配音、字幕、
音效和配乐后导出终片。

### 1.2 核心价值

1. **可控**：用户能看到每个分镜的合同、源码、产物和门禁；
2. **可改**：改单镜不必重做全片；
3. **可复现**：同一版本、输入和帧得到同一画面；
4. **可信**：界面状态来自真实运行和产物；
5. **可恢复**：失败、取消、刷新和重试不丢失已完成工作；
6. **可迁移**：核心合同能与未来视频生产项目共享。

### 1.3 产品原则

- 节点代表用户可理解的产物承诺，不代表后端实现细节；
- 模型负责创造性判断，程序负责可确定完成的工作；
- 失败必须指出对象、阶段、原因和下一步；
- 空能力应明确显示未实现，不得伪装成已完成；
- 生成内容必须经过应用验证才能成为可渲染产物；
- 用户数据和密钥默认不进入客户端日志或产物。

## 2. 目标用户与 Jobs-to-be-Done

### 2.1 技术内容创作者

当我有一段技术稿件时，我希望快速获得结构清晰、视觉可信的短视频，并能针对某一镜
调整表达或动画，而不必手工重做整条时间线。

### 2.2 教育与科普创作者

当我需要把抽象概念拆成逐步画面时，我希望系统给出可检查的语义分镜和视觉合同，并
确保字幕、配音和画面时序一致。

### 2.3 独立创作者与小型工作室

当模型调用或渲染失败时，我希望看到真实原因、重试单镜并保留已完成结果，而不是
重新运行整条黑盒流水线。

## 3. v3 范围

### 3.1 In scope

- 项目创建和稿件导入；
- 语义拆分、全局创意方向和分镜合同；
- 动态物化分镜通道；
- 单镜代码生成、提取、检查、编辑、重新生成和只重渲；
- 支持完整 HTML 与明确分段代码的兼容导入；
- 结构化 JSON/tree/table/raw 可视化；
- 配音、字幕、音效、配乐和音画对齐；
- 单镜规则 QA、视觉 QA 和最终媒体 QA；
- 一键运行、取消、失败重试、刷新恢复；
- 项目/分镜/产物/门禁/执行轨迹的真实 UI；
- 本地开发数据迁移和历史项目保护；
- 版本化工作流与可重放验收。

### 3.2 Out of scope

- 用户注册、登录、团队成员与权限；
- 在线协同编辑；
- 计费、套餐、配额销售；
- 公网对象存储产品化；
- 移动端原生应用；
- 自托管执行控制面；
- 通用可视化工作流编排平台；
- 暴露模型隐藏思维链；
- 自动合并 PurpleInk 整个应用或业务数据库。

### 3.3 Future candidates

登录、多 workspace、团队协作、云端 artifact、共享模板市场和发布审批属于后续版本。
v3 的数据与合同必须允许后续增加这些能力，但不得提前实现空壳。

## 4. 用户可见领域模型

### 4.1 Project

项目包含原始稿件、全局创意方向、分镜、运行历史、媒体配置、产物和最终导出。

### 4.2 Canvas

Canvas 是项目流程的可视化投影。全局节点负责导入、拆分、配乐和导出；每个分镜通道
展示脚本/合同、代码视频、音频、字幕和 QA。

### 4.3 Shot

Shot 是独立的语义和渲染单位。每个 Shot 必须拥有稳定 ID，并能独立：

- 查看合同；
- 生成或修正代码；
- 渲染；
- 生成/调整媒体；
- 运行 QA；
- 标记失败、过期或成功。

### 4.4 Run

Run 表示一次用户明确发起的工作流执行。用户可以启动、取消、查看阶段、错误、重试
次数和最终结果。

### 4.5 Artifact

Artifact 是不可变的版本化结果，包括 JSON 合同、源码包、编译 bundle、缩略图、音频、
字幕、单镜 MP4、QA 报告和终片。页面下载必须使用 artifact ID，而不是本机路径。

### 4.6 Gate

Gate 是应用对输入、源码、编译、帧或媒体做出的真实验收。每个 Gate 结果必须包含
名称、状态、问题和对应 artifact/版本。

## 5. 用户可见状态

| 状态 | 用户含义 |
|---|---|
| 空闲 | 尚未请求执行 |
| 可运行 | 依赖已满足，可以启动 |
| 排队中 | 请求已接受，等待资源 |
| 运行中 | 正在执行且有真实运行记录 |
| 成功 | 本节点承诺的产物和门禁已完成 |
| 失败 | 当前尝试失败，保留已完成 checkpoint |
| 已取消 | 用户或系统明确取消 |
| 已过期 | 上游变更使旧结果不再可用 |
| 被阻塞 | 由依赖/配置派生，必须显示阻塞原因 |

“被阻塞/可运行”是 readiness，不得与“排队中/运行中”等执行状态混为一谈。

## 6. 核心用户旅程

### 6.1 创建与导入

1. 用户创建项目；
2. 输入或上传 `.txt/.md` 稿件；
3. 可选配置画幅、语言、目标时长和媒体偏好；
4. 系统确认项目和导入节点已创建；
5. 用户启动语义拆分。

### 6.2 语义拆分与分镜

1. 系统返回结构化项目计划；
2. 前端用组件化 JSON 视图展示段落、分镜和警告；
3. 系统物化 N 个稳定 Shot 通道；
4. 用户可以在继续前检查和调整分镜顺序/文字。

### 6.3 单镜生成

1. 系统生成 ShotSpec；
2. 系统生成结构化代码 source；
3. UI 显示已提交的 raw source artifact、提取字段和兼容警告，不展示模型隐藏内容；
4. 应用门禁通过后编译和渲染；
5. UI 显示预览、源码、门禁和执行轨迹。

### 6.4 局部修改

- 修改文字/视觉参数使相关下游结果变为过期；
- “重新生成”允许再次调用模型；
- “只重渲”必须复用同一 canonical source，不调用模型；
- patch 必须引用 base artifact hash，避免覆盖错版本。

### 6.5 媒体与合成

- 配音、字幕、音效和配乐均显示真实产物；
- 音频与字幕按时间轴对齐；
- 全部 required Shot 成功后才允许最终合成；
- 最终导出后显示真实媒体检测结果和下载入口。

### 6.6 取消、失败与恢复

- 取消后不再派发新工作；
- 当前工作尽快停止并清理临时资源；
- 已提交 artifact 保留；
- 刷新页面后仍看到真实状态；
- 重试只重做失败/过期且未命中 checkpoint 的部分。

## 7. 功能需求

### 7.1 Foundation 与项目

- `PROD-FOUND-001`：系统必须支持创建、重命名、查看项目。
- `PROD-FOUND-002`：项目创建必须原子地产生所需全局节点。
- `PROD-FOUND-003`：系统必须为每个项目记录工作流版本。
- `PROD-FOUND-004`：历史项目迁移前必须可备份和清点。
- `PROD-FOUND-005`：历史导入失败不得破坏原数据库或已导入项目。

### 7.2 稿件与计划

- `PROD-PLAN-001`：用户必须能输入或上传 UTF-8 文本稿件。
- `PROD-PLAN-002`：系统必须输出结构化项目计划，而不是只有自由文本摘要。
- `PROD-PLAN-003`：项目计划必须包含稳定 Shot 标识、原文范围和顺序。
- `PROD-PLAN-004`：前端必须提供 JSON tree/table/raw 视图。
- `PROD-PLAN-005`：解析问题必须定位到字段或原文区间。
- `PROD-PLAN-006`：用户确认或系统策略允许后才能物化 Shot 通道。

### 7.3 Canvas

- `PROD-CANVAS-001`：Canvas 必须支持平移、缩放和自动布局。
- `PROD-CANVAS-002`：Shot 通道必须由计划动态生成，不由用户手工连线。
- `PROD-CANVAS-003`：节点必须显示真实 readiness 和执行状态。
- `PROD-CANVAS-004`：选择节点必须打开对应真实 Inspector 数据。
- `PROD-CANVAS-005`：一个 Shot 失败不得抹除其他 Shot 成功结果。
- `PROD-CANVAS-006`：上游变更必须使受影响下游结果显式过期。

### 7.4 AI 与模型设置

- `PROD-AI-001`：用户必须能配置支持的 provider 凭据和模型路由。
- `PROD-AI-002`：凭据必须只在服务端处理，保存后不得回显。
- `PROD-AI-003`：设置页显示的 provider/model 必须与真实调用一致。
- `PROD-AI-004`：模型失败必须区分凭据、限额、网络、结构和内容问题。
- `PROD-AI-005`：执行轨迹可以显示 Tool 与用户可见摘要，禁止显示隐藏思维链。
- `PROD-AI-006`：替换模型不得改变项目业务接口和已有 artifact 可读性。

### 7.5 ShotSpec 与代码生成

- `PROD-SHOT-001`：每个 Shot 必须有版本化 ShotSpec。
- `PROD-SHOT-002`：尺寸、帧率、时长、seed 和 artifact 路径由应用决定。
- `PROD-SHOT-003`：模型输出必须先转为结构化 source，再进入渲染。
- `PROD-SHOT-004`：系统必须兼容提取单一完整 HTML。
- `PROD-SHOT-005`：系统必须兼容提取标记明确的分段 HTML/CSS/JS。
- `PROD-SHOT-006`：含多个候选、未知脚本或无法唯一解释的输入必须拒绝。
- `PROD-SHOT-007`：前端提取预览不得替代服务端权威门禁。
- `PROD-SHOT-008`：用户必须能查看 canonical fragments 和兼容警告。
- `PROD-SHOT-009`：局部 patch 必须绑定 base artifact hash。
- `PROD-SHOT-010`：只重渲不得产生新的模型调用。

### 7.6 渲染与确定性

- `PROD-RENDER-001`：同一版本和输入的同一帧必须得到相同像素。
- `PROD-RENDER-002`：渲染前必须完成安全、语法和确定性门禁。
- `PROD-RENDER-003`：渲染必须支持单镜独立执行和重试。
- `PROD-RENDER-004`：渲染成功必须产生可播放 MP4 与预览图。
- `PROD-RENDER-005`：成功状态必须有真实媒体探测和实体 hash。
- `PROD-RENDER-006`：缓存命中必须能解释命中的 input/bundle/version。

### 7.7 媒体

- `PROD-MEDIA-001`：配音、字幕、音效和配乐必须使用版本化 artifact。
- `PROD-MEDIA-002`：字幕必须可追溯到文字和时间码来源。
- `PROD-MEDIA-003`：音频生成失败不得伪装成静音成功。
- `PROD-MEDIA-004`：用户选择不生成某类音频时必须显式记录为配置，而非缺失。
- `PROD-MEDIA-005`：媒体时长必须与 Shot/项目时轴可验证地对齐。

### 7.8 QA 与导出

- `PROD-QA-001`：规则 QA 与视觉 QA 必须分别显示结果。
- `PROD-QA-002`：视觉模型报告不能覆盖确定性规则失败。
- `PROD-QA-003`：最终导出 readiness 必须由唯一策略派生。
- `PROD-QA-004`：终片必须验证视频流、required 音频流、字幕合同、尺寸和时长。
- `PROD-QA-005`：终片下载必须通过 artifact ID。
- `PROD-QA-006`：最终实体 SHA-256 必须与记录一致。

### 7.9 运行控制与恢复

- `PROD-RUN-001`：用户必须能一键启动整个项目。
- `PROD-RUN-002`：用户必须能取消活动 Run。
- `PROD-RUN-003`：重复启动同一输入不得产生重复副作用。
- `PROD-RUN-004`：刷新/重连后状态必须与持久化业务事实一致。
- `PROD-RUN-005`：重试必须复用已成功且输入未变化的 checkpoint。
- `PROD-RUN-006`：失败必须显示阶段、对象、错误类别和可操作建议。
- `PROD-RUN-007`：页面必须区分实时连接状态和业务执行状态。

### 7.10 UI 真实性与设计系统

- `PROD-UI-001`：每个可见字段必须有真实数据来源。
- `PROD-UI-002`：无实现的数据必须显示为禁用、空态或明确占位。
- `PROD-UI-003`：可点击外观必须对应真实操作。
- `PROD-UI-004`：Loading/Skeleton 只能覆盖真实异步窗口。
- `PROD-UI-005`：新增视觉组件必须来自设计真源并登记组件手册。
- `PROD-UI-006`：Inspector 必须提供数据、源码、门禁、执行四类视图。
- `PROD-UI-007`：错误、警告和成功状态不得只依赖颜色表达。

## 8. 非功能产品要求

### 8.1 可复现

- `PROD-NFR-DET-001`：版本、输入、资产与 seed 必须足以重放单镜。
- `PROD-NFR-DET-002`：工作流/编译器升级必须使旧缓存显式失效。

### 8.2 可恢复

- `PROD-NFR-REC-001`：进程或页面退出不得丢失已提交业务事实。
- `PROD-NFR-REC-002`：临时资源不得被当成成功 artifact。

### 8.3 隐私与安全

- `PROD-NFR-SEC-001`：凭据不得进入客户端 bundle、日志、artifact 或对话输出。
- `PROD-NFR-SEC-002`：模型代码不得在通过应用门禁前执行。
- `PROD-NFR-SEC-003`：用户下载不得暴露服务器绝对路径。

### 8.4 性能与反馈

- `PROD-NFR-PERF-001`：用户命令被接受后必须在 2 秒内显示真实排队/启动反馈。
- `PROD-NFR-PERF-002`：长任务必须提供阶段级进度，不要求伪造连续百分比。
- `PROD-NFR-PERF-003`：改单镜不应强制重跑无关 Shot。

### 8.5 可访问性

- `PROD-NFR-A11Y-001`：核心操作必须可键盘访问。
- `PROD-NFR-A11Y-002`：状态和错误必须有文本标签。
- `PROD-NFR-A11Y-003`：应用 UI 动效必须尊重 reduced motion。

## 9. 产品验收场景

### `SCN-01` 新项目完整成片

导入中文稿件 → 生成多个 Shot → 逐镜生成/渲染 → 生成媒体 → QA → 导出终片。
终片可播放，UI 所有成功节点都有 artifact 和门禁证据。

### `SCN-02` 单镜定向修改

修改一个 Shot 的视觉要求，只使该 Shot 的 source/render/QA 过期；其他 Shot 不重跑。

### `SCN-03` 完整 HTML 兼容导入

导入只包含一个合法完整 HTML 的旧产物，前端展示提取 fragments，服务端复验后生成
canonical source；未知外链脚本版本必须被拒绝并指出原因。

### `SCN-04` 分段代码

输入明确标记的 body/CSS/setup/timeline 四段；系统唯一映射。除 body 外的字段可
显式为空，但含重复候选或额外正文时拒绝。

### `SCN-05` 失败与重试

一个 Shot 在模型或渲染阶段失败；其他 Shot 继续保留。修复配置后重试只执行失败和
受影响步骤，不重复已提交 checkpoint。

### `SCN-06` 取消与刷新

运行中取消并刷新页面；UI 显示已取消或已完成的真实终态，不出现永久“运行中”。

### `SCN-07` 历史数据保护

旧数据库先备份，再导入新系统；项目、节点、artifact 指针完成计数对账，失败可回到
原数据读取。

### `SCN-08` UI 无假值

对项目、Canvas、Inspector、设置和导出页面逐字段核验；不存在固定百分比、恒真检测、
无链接 artifact、可点但无行为的控件。

## 10. 成功指标

v3 完成时：

- `SCN-01` 至 `SCN-08` 均有可重放证据；
- 单 Shot 失败不会清空其他 Shot；
- 只重渲产生 0 次模型调用；
- 同帧重复捕获 hash 一致；
- required 最终媒体流 100% 通过探测；
- UI 字段来源矩阵无 `unknown`；
- 历史导入计数差异为 0 或有逐项可解释报告；
- 活动主路径不存在双数据库、双调度器、双 Agent Runtime 或双帧时钟。
